# 평가계획 정보공시

초등 교수·학습 및 평가계획의 정보공시 적합성을 판정하고, 성취기준별 공식 성취수준을 적용하여 원본 형식을 보존한 개정 HWP를 만든다.

## 기준 확인

작업 전에 [references/2026-elementary-revisions.md](references/2026-elementary-revisions.md)를 전부 읽는다. 사용자가 별도 개정 안내나 지침서를 제공하면 그 문서를 우선 기준으로 삼고, 참고문서와 충돌하는 부분을 명시한다.

## 공식 성취수준 적용

2022 개정 교육과정의 성취기준별 성취수준은 이 스킬에 포함된 `references/official-achievement-levels-2022.json`을 사용한다. 이 자료는 사용자가 제공한 1~2, 3~4, 5~6학년군 공식 HWP 3개에서 성취기준별 A·B·C 문장을 추출한 것이다. 전체 JSON을 직접 탐색하지 말고 `scripts/lookup_official_levels.py`로 필요한 코드만 조회한다.

1. 평가 행의 대괄호 안 성취기준 코드를 모두 추출한다.
2. 코드 앞자리로 학년군을 선택한다: `2`는 1~2학년군, `4`는 3~4학년군, `6`은 5~6학년군이다.
3. 다음처럼 조회한다.

```powershell
python scripts/lookup_official_levels.py 2국01-01 4수03-10 6국02-01
```

4. 학교 단계명에는 `A → 잘함`, `B → 보통`, `C → 노력요함`으로 대응시킨다.
5. 공식 문장을 요약·의역·문체 통일하지 않고 그대로 넣는다. 공식 원문에 `~할 수 있다`가 있으면 그대로 보존한다.
6. 한 평가 행에 코드가 여러 개면 문서에 적힌 코드 순서대로 각 코드의 같은 단계 문장을 이어 붙인다. 완전히 같은 문장은 한 번만 남긴다.
7. 코드가 자료에 없으면 임의 문장을 만들지 않는다. 누락 코드와 해당 행을 보고하고, 최신 공식 자료나 사용자 확인을 요청한다.
8. 기존 성취수준과 공식 문장이 다르면 공식 자료를 우선하며, 변경한 코드 수와 미검색 코드 수를 검증 결과에 밝힌다.

## 작업 흐름

1. 제공된 안내문과 평가계획을 모두 연다. HWP/HWPX는 한글 COM 자동화가 있으면 `GetTextFile("TEXT", "")`로 텍스트를 추출하고 PDF로 내보내 표 구조도 확인한다.
2. 현재 열을 필수 항목과 대조한다. 내용상 동등한 `평가시기`는 `시기`로 인정하되, 공식 복합 표제는 정확히 맞춘다.
3. 원본을 수정하지 않는다. 새 파일명에 `_개정양식`, `_정보공시용` 등 목적을 드러내는 접미사를 붙인다.
4. 다음 공식 표제를 기본으로 사용한다.
   - `평가시기`
   - `단원명(교수·학습 내용)`
   - `평가 요소`
   - `평가 영역`
   - `평가 방법 및 횟수`
   - `성취기준`
   - `성취수준`
5. `수업 방법`, `수업·평가 연계의 주안점`은 새 정보공시 표에서 제거한다. 개정 전·후 비교 예시라면 개정 전 표는 보존한다.
   - `[토의·토론 수업]`, `[토의토론 수업]`, `[탐구 학습]`, `[활동 중심 학습]`, `[역할극]` 같은 괄호형 수업 방법명은 삭제한다.
   - 수업 방법명 뒤에 있는 실제 학습 활동 문장만 `단원명(교수·학습 내용)`으로 옮긴다.
   - 수업 방법명 자체를 교수·학습 내용으로 옮기지 않는다.
6. `평가 기준`을 제목만 `성취수준`으로 바꾸지 않는다. 각 행의 성취기준 코드를 조회하여 공식 A·B·C 문장으로 교체한다.
7. 평가 횟수는 근거가 있을 때만 기입한다. 한 행이 한 번의 평가임이 명백한 예시는 `관찰 평가 / 1회`처럼 쓸 수 있다. 실제 계획의 횟수가 불명확하면 임의로 전부 `1회` 처리하지 말고 사용자에게 확인하거나 미확정 항목으로 보고한다.
8. 표 안의 공식 용어, 공백, 가운데점 `·`, 괄호를 함께 점검한다.
9. 한글의 쪽 나눔 때문에 머리글 없이 별도 표로 이어진 연속표도 반드시 변환한다. 첫 행에 `수업·평가 방법`이 없더라도 기존 평가 행 구조가 확인되면 같은 표로 인식한다. 연속표의 `평가시기`도 맨 왼쪽 열로 이동하고, 첫 평가 행이 반복 머리글로 처리되지 않도록 한다.

## HWP 자동화

Windows와 한글이 설치된 환경에서는 다음 순서를 사용한다.

1. 워크스페이스 의존성을 불러와 번들 Python 경로를 확인한다.
2. `scripts/revise_hwp.ps1`에 원본 HWP, 결과 HWP, Python 실행 파일을 전달한다.
3. 스크립트가 만든 HWP를 다시 열어 표제 변경을 확인한다.
4. 각 평가 행의 성취기준 코드를 공식 성취수준 자료와 대조한다.
5. 각 평가 행의 실제 횟수는 문서 근거에 따라 채운다.

```powershell
& scripts/revise_hwp.ps1 `
  -InputPath "원본.hwp" `
  -OutputPath "결과_개정양식.hwp" `
  -PythonExe "번들-python.exe"
```

입력이 HWPX이면 `scripts/update_hwpx_headers.py`를 직접 실행한다.

```powershell
& "번들-python.exe" scripts/update_hwpx_headers.py 원본.hwpx 수정.hwpx
```

한글 COM을 사용할 수 없으면 HWP를 억지로 변환하지 않는다. 사용자에게 HWPX로 다시 저장한 파일을 요청하거나, 사용 가능한 문서 변환기로 복사본을 변환한다.

## 검증

완료 전에 다음을 모두 확인한다.

- 결과 HWP를 한글로 다시 열 수 있음
- `단원명(교수·학습 내용)`과 `평가 방법 및 횟수`가 존재함
- 새 표에 `수업·평가 연계의 주안점`과 `평가 기준`이 남아 있지 않음
- `단원명(교수·학습 내용)`에 괄호형 수업 방법명이 남아 있지 않고 실제 활동 내용은 보존됨
- 모든 성취기준 코드가 내장 공식 자료에서 검색되며, `잘함·보통·노력요함`이 각각 A·B·C 원문과 정확히 일치함
- 공식 성취수준의 종결 어미와 문장 부호가 원문 그대로 보존됨
- 여러 성취기준이 있는 행은 코드별 공식 문장이 순서대로 반영됨
- 평가 횟수가 누락되거나 근거 없이 일괄 입력되지 않음
- PDF로 내보내 모든 페이지를 확인했으며 표 잘림, 겹침, 과도한 줄바꿈이 없음
- 머리글 없는 연속표까지 포함하여 원본과 결과의 평가 항목 수 및 `평가시기` 값을 항목별로 대조함
- 원본 파일이 보존됨

최종 답변에는 변경 내용, 공식 성취수준 일치 건수, 미검색 코드와 검증 결과를 짧게 밝히고 결과 HWP만 연결한다. 중간 HWPX, PDF, PNG는 사용자가 요청하지 않는 한 제공하지 않는다.
